# Plan: P1 — in-browser mock API and synthetic seed

## Goal
Every `/api/*` route of `contract/openapi.json` answers from an in-browser store, seeded with 14 synthetic patients.

## Context
- **Spec:** `spec.md` (goal, scope, decisions, acceptance). Do not repeat it here.
- **Base commit:** `ac802ad` (branch `feat/mock-demo`).
- **Phase:** P1 only. Design polish, intro, tour UI, AI trace UI, MCP panel and deploy are later phases.
- **Commands:** `pnpm` is not global. Use `npx -y pnpm@10 <script>`. Below, `P` = `npx -y pnpm@10`.

### Design rules for all mock tasks
- `src/mock/**` and `test/**` run in two places: Vite (browser) and Node's built-in test runner (type stripping, Node ≥ 22.18; local is 26).
  - Runtime imports inside `src/mock/**`: relative, with the `.ts` extension.
  - `@/` paths only in `import type` lines (Node erases them).
  - Types come from `@/api` (`components`, `paths`). Never import `@/lib/api` from `src/mock/**`: it pulls in `openapi-fetch` and the Vite-only seed.
  - `import.meta.glob` lives only in `src/mock/index.ts`. No other mock file is Vite-specific.
- Test runner choice: `node --test`, no new dependency. Reason: the store mutations and the router have real edge cases. `tsc` alone cannot check them. A dev assertion runs only in a browser.
- `test/**` is type-checked by `tsconfig.node.json` (Node types). `tsc -b` therefore checks the tests too.

- **Behavior:**
  - `Scenario` holds: `patient`, `insurer: InsurerCode` (`'111'|'201'|'205'|'207'|'209'|'211'|'213'`), `triggers: ScenarioTrigger[]`, `requests`, `timeline`, `contacts`, `reports: Report[]` (id, date, title, text), optional `live` (a `ScenarioTrigger` that `POST /api/triggers` uses, see T6).
  - `ScenarioTrigger` holds `trigger`, `candidates`, `duplicate_alert`, `insurer_request`, optional `verdicts: Record<candidateId, VerdictVersion[]>`.
  - `createStore` deep-copies the scenarios (`structuredClone`). `store.reset()` restores the start state.
  - Reads: `patients(q?)`, `triggers()`, `getCase(id)`, `timeline(patientId, type?, q?)`, `queue()`, `stats()`, `verdicts(triggerId, candidateId)`, `lookupContact(orgId)`.
  - `patients(q)` matches `id`, `name`, `rc`, case-insensitive substring.
  - `TriggerSummary` is derived on each read, never stored:
    - `status_counts`: by `status` over relevant candidates (`decision === 'relevant'`, or no decision and `verdict.label === 'relevant'`; same rule as `classify()` in `src/lib/case.ts`).
    - `to_decide`: candidates with `verdict.label === 'uncertain'` and no decision.
    - `open_requests`: requests of the trigger not in `received`/`not_found`.
    - `duplicate`: `duplicate_alert !== null`.
  - `Candidate.request_id` and `Candidate.request_state` are derived from the requests on each read. The requests are the single source.
  - `RequestItem.contact` is derived from the contacts map on each read.
  - `timeline()` returns the scenario events plus one `type: 'trigger'` event per trigger, date-sorted. `type` filters by event type. `q` matches `title`/`detail`, case-insensitive.
  - `verdicts()` with no stored history returns one version `{ n: 0, verdict: candidate.verdict, active: true }`.
  - `stats()`: `patients` = patient count. `studies` = candidates over all triggers. `in_pacs` = those with status `available` or `missing_report`. `by_modality` and `by_year` group the same set (`key` = modality / first 4 chars of date; undated → `neznámý`).
  - Unknown id → throws `NotFound`.
- **Acceptance:**
  - Each read returns a value that type-checks as the 200 body of its route in `paths`.
  - A candidate whose request is `not_delivered` reads back with `request_state: 'not_delivered'`.
  - `reset()` after a direct state change returns the fixture start state.
  - A patient with only a `live` trigger shows in `patients()` but not in `triggers()`.
- **Test cases:** summary counts (relevant/uncertain/decided mix); request_state derivation; contact derivation; patient search by name and RČ; timeline type and q filters; trigger events in timeline; verdicts default v0; stats grouping incl. undated; NotFound on unknown trigger; reset.

### T6 — Store mutations
- **Mode:** `full`
- **Depends on:** T5
- **Files:**

  | Path | Change | Symbols |
  |---|---|---|
  | `src/mock/store.ts` | modify | `createTrigger`, `addCandidate`, `decide`, `rejudge`, `restore`, `approve`, `requested`, `notFound`, `saveContact`, `deliver`, `pacsArrival` |
  | `test/store.test.ts` | modify | — |

- **Behavior:**
  - `createTrigger(body)`: patient has `live` → creates that trigger with id `live.trigger.id`, `kind`/`modality`/`date` from the body, `simulated: true`. A second call for the same patient returns the existing summary. Patient without `live` → see Open Question Q1. Returns `TriggerSummary`.
  - `addCandidate(triggerId, body)`: `source: 'collector'`, `decision: 'relevant'`, verdict `relevant` with reason "Přidal/a koordinátor/ka.". `place` or `organization_id` given → status `missing`, else `place_unknown`. Creates one `draft` request. Returns `Case`.
  - `decide(triggerId, candidateId, body)`: sets `decision` and `decision_reason`. `relevant` on a non-available candidate with no request → creates a `draft` request. `not_relevant`/`removed` → deletes its `draft` request. Returns `Case`.
  - Request channel on create: contact has `fhir_endpoint` → `fhir`; contact has `email` → `email` with an `email_draft`; else `phone`.
  - `rejudge(triggerId, candidateId, note)`: appends version `n+1`, `active: true`, earlier versions `active: false`. Verdict: the scenario's prepared `rejudge` verdict for that candidate if set, else the same label with a reason that cites the note. Sets `trace` from `llmTrace` for that candidate. Updates `candidate.verdict`. Returns `Case`.
  - `restore(triggerId, candidateId, n)`: appends a new active version with `restored_from: n` and the verdict of version `n`. Returns `Case`.
  - `approve(id)`: `draft` → `sent`, `sent_at` = now. `requested(id)`: `draft`/`not_delivered` → `requested`. `notFound(id)`: → `not_found`. Return `RequestItem`.
  - `deliver(id)`: → `received`. Candidate status → `available`, `pacs_source` set. Adds one `imaging` timeline event with `simulated: true` and `resource: ImagingStudy/<study_id>`. Returns `RequestItem`.
  - `saveContact(orgId, body)`: sets `email`/`phone`, `verified_at` = now, `needs_reverify: false`. Creates the contact if missing (name from a request with that `organization_id`). Returns `Contact`.
  - `pacsArrival(studyId)`: the timeline event with `resource: ImagingStudy/<studyId>` loses detail `bez snímků v PACS`. A candidate with that `study_id` → status `available`, its request → `received`. Returns `{ rows: 1, patched: n, unchanged: 0, unmatched: 0 }` (`unmatched: 1`, `patched: 0` if no match).
  - Unknown id → `NotFound`. Illegal state change (for example `approve` on `received`) → throws `Conflict`.
- **Acceptance:**
  - After `approve`, `queue()` and `getCase()` both show the new state.
  - After `deliver`, `getCase()` progress counts the prior as ready, and `stats().in_pacs` grows by 1.
  - `createTrigger` for the `live` patient makes the trigger appear in `triggers()`. `reset()` removes it.
  - `restore(…, 0)` makes `candidate.verdict` equal the original verdict.
- **Test cases:** one per mutation (happy path); decide relevant creates draft; decide removed deletes draft; channel selection fhir/email/phone; rejudge twice then restore; approve on received → Conflict; pacs-arrival no match; createTrigger twice; reset after mutations.
- **Not in this task:** HTTP status mapping, latency.
- **Verification:**
  - `node --test test/store.test.ts test/trace.test.ts`
  - `npx -y pnpm@10 lint`
